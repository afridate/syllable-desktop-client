# Lyrica

Текст песни синхронизируется с музыкой слово в слово, слог в слог. Слова появляются на экране точно под ритм, а внешний вид (цвета, скорость анимации) подстраивается под обложку трека и его звучание (BPM, энергичность, тембр).

Название проекта - Lyrica, домен - [lyricapp.ru](https://lyricapp.ru).

## Как это работает

Системный плеер (Spotify, Apple Music, YouTube Music и т.п.) определяется через `playerctl` на Linux (или через `windows.py` на Windows).

Получившийся `master_sync.json` уходит на сервер и кэшируется - при повторном прослушивании трека всё уже готово и заново обрабатывать не надо. Браузерный клиент получает этот JSON по WebSocket и анимирует слова в реальном времени: активное слово подсвечено, уже прозвучавшие - гаснут.

## Архитектура

![Архитектура Lyrica](Architecture.jpeg)

Если коротко: `server.py` - точка входа, который умеет и в WebSocket (обработчик соединения с клиентом, отдаёт данные трека), и в обычный HTTP (отдаёт статику и аудиофайлы). Источник данных - `track_provider.py`, который либо берёт трек из локальной папки `audio/`, либо стучится в `api.lyricapp.ru`. На клиенте `player.js` хранит состояние (список треков, текущая песня, статус воспроизведения) и через набор функций отрисовки (`renderLyrics`, `updateProgress`, `applyTheme` и т.д.) собирает то, что видит пользователь - текст, прогресс-бар, тему оформления - и сам HTML Audio Element, который всё это проигрывает.

## Структура репозитория

```
.
├── frontend/
│   ├── index.html         # разметка плеера
│   ├── player.js          # рендер текста, анимация, разбор beat_id в секунды
│   ├── style.css          # тёмная тема, свечение под цвет обложки
│   ├── server.py          # локальный WebSocket-сервер (ws://localhost:8765)
│   ├── track_provider.py  # получение трека
│   ├── mock_response.json # пример master_sync.json для разработки без бэкенда
│   └── config.py          # локальные настройки (см. предупреждение ниже)
├── backend/                # сервер: FastAPI + PostgreSQL
│   ├── winsdk.py           
├── linux.py                 # слушатель медиаплеера на Linux
└── windows.py                # слушатель медиаплеера на Windows
```

## Формат данных - master_sync.json

Тайминги привязаны не к секундам, а к id бита - так и место экономится, и снаппинг под музыку получается точнее.

```json
{
  "d": { "n": "название трека", "a": "артист" },
  "bpm": 161.5,
  "off": 0.0,
  "vibe": { "energy": 3.757, "brightness": 0.235, "roughness": 0.492 },
  "theme": { "color_pallete": { "primary": "#C2C2C2", "secondary": "#2A2A2A", "accent": "#5C5C5C" } },
  "words": [
    ["Ван|на,", 71.3, 3, [0.0, 1.5]],
    ["крас|ный", 72.3, 4, [0.0, 2.0]]
  ]
}
```

| Поле | Значение |
|---|---|
| `bpm` / `off` | темп трека и смещение первого бита в секундах - всё остальное привязано к ним |
| `vibe.energy` | общая энергичность и громкость трека |
| `vibe.brightness` | преобладание высоких или низких частот, влияет на толщину шрифта |
| `vibe.roughness` | насколько "забит" спектр (шумный рок против чистого эмбиента) |
| `theme.color_pallete` | основные цвета обложки, на них строится вся палитра интерфейса |
| `words[i]` | `["слог|слог", beat_id, duration_beats, [смещения слогов от beat_id]]`. Если слог один - последнего элемента массива просто нет |

Перевод beat_id в секунды (см. `player.js`):

```js
seconds = offset + (mainBeat + subBeat / 4) * (60 / bpm)
```

## Запуск фронтенда локально

```bash
cd frontend
python server.py        # поднимет WebSocket на ws://localhost:8765
# открыть index.html в браузере
```

`track_provider.py` отдаёт реальный трек через `api.lyricapp.ru/tracks/get`.
